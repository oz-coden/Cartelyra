# Cartelyra 要件と操作仕様

## 目的

神奈川大学 横浜キャンパス内で、建物・部屋・トイレなどの設備・門を探し、登録された接続に沿った経路を確認できる非公式の案内サイトを提供する。

公開物はHTML・CSS・JavaScript・JSONからなる静的サイトとする。地図の表示、検索、場所の選択、経路計算はブラウザー内で完結し、専用サーバー・データベース・ログインを必須にしない。

23号館はB2〜8Fの10フロア・286区画を表示する。255区画は通路側へ直接、31区画は手前の部屋まで暫定案内する。23-B203は23-B202、23-107は23-105の通路側まで暫定案内し、B2下側階段は共用通路への接続を補完しない。EV3系統と対応する階段を隣接階へ仮接続し、B1と1Fは連続する階として扱う。1Fの近接開口は左右各1出入口にまとめ、出入口1を15号館側、出入口2を20号館側とする。17号館・23号館間の地上通路から両出入口へ参考接続する。扉位置・通行条件は現地照合待ちとする。[23号館の図面登録と確認項目](building-23-review.md)に用途と暫定進入関係の確認項目を記録する。

建物・階・設備・門はJSONで管理する。出典と確認状態を記録し、棟を増やすたびに画面の分岐を追加する設計にしない。

初期表示はキャンパス図とする。建物を選ぶとその建物の平面図へ切り替える。キャンパス図では特定の建物・階を検索候補の優先対象にしない。

表示モード名は「キャンパス図」「平面図」「立体図」、設備の表示名は「EV」、未確認接続を含む案内の表示は「参考ルート」に統一する。検索では「エレベーター」「エレベータ」もEVとして受け付け、番号を含む入力にも対応する。

検索は空白で区切った複数語に対応する。独立した号館名・階の語は完全一致で絞り込み、「3号館」を「23号館」に、「2F」を「B2F」に部分一致させない。室名や用途の語は引き続き部分一致で検索する。

## 状態の分離

| 状態 | 役割 | 他の状態への影響 |
| --- | --- | --- |
| 表示モード | キャンパス図・平面図・立体図 | 出発地・目的地を保持する |
| 表示する棟・階 | 図面と階内の場所一覧を指定 | 出発地・目的地を変更しない |
| 選択した場所 | 強調表示と共通の詳細・アクションを表示 | 同じ棟・表示中の連絡棟群ではカメラを維持。別棟へ切り替える場合はその棟を表示範囲に収める |
| 出発地・目的地 | 検索または選択した場所から明示的に指定 | 経路計算だけで表示階・選択・カメラを変更しない |
| 地図で指定中の対象 | 出発地または目的地の一方 | 設定完了・キャンセル・Escapeで解除する |
| 立体図の全階表示・展開率 | 可視階と階間隔を指定 | 部屋・設備の選択や経路計算で変更しない |
| カメラ | 位置・方向・拡大率 | ドラッグ等の手動操作、全体を表示、立体図への切り替え、建物選択、明示的な道順カード操作で変更する |

## 連絡棟

屋内・屋根付き通路でつながる棟は、棟ID・階名を保持したまま平面図・立体図でまとめて表示できるようにする。一体表示が既定で、単棟表示へ切り替えられる。階番号が異なっても対応する表示レベルを明示する。立体図の階展開は共通レベル順にそろえ、表示範囲内の棟を選んでもカメラを維持する。表示グループの所属から接続を推定しない。7〜10号館は1〜6Fを一体表示し、10号館は1〜4Fを含める。2Fは2023年作成の参考PDFを基に、既存階と共通の独自描画ルールで仮登録する。既存階の配置・区画・室番号は2024年の掲示写真を優先し、PDFの一般的用途名は現用途未確認の履歴情報として補足する。個人名・内線番号・研究テーマは収録しない。8号館のEVと共用階段は隣接階を仮接続し、他棟の1F階段との対応は確認待ちとする。2〜4Fの7・10号館境界は高低差未確認の段差接続とする。7・8号館直通は3F以上のみで、2Fは7号館側に屋外へ下りる階段を設ける。2Fの7号館から他棟への階段回避経路は未登録。3F以上は8・9号館側の平坦な連絡を使える。7号館2Fと8号館1F・2Fの明示した階段から屋外へ参考接続する。8号館の中間踊り場は屋外ノードで表し、1Fから上る・2Fから下りる方向を保持する。EV脇の階段から中庭へも接続する。資料間の不一致・奥の部屋の進入元・屋外接続は確認待ちとして保持し、測量後に形状・距離・接続を見直す。

## 共通の場所選択

1. 平面図・立体図・検索・場所一覧・門一覧から同じ場所IDを選択する。
2. 選択した場所の名前と登録状態を、その場所を指す地図上の吹き出しに表示する。「ここから出発」「ここへ行く」を吹き出し内に配置する。
   - 吹き出しは地図に重ね、表示・非表示によってページのレイアウトやスクロール位置を変更しない。
   - 平面図・キャンパス図のパン／ズーム、立体図のカメラ操作・階の展開、画面サイズの変更に追従する。
   - 地図の端では吹き出しを表示範囲内に収める。選択位置が画面外・カメラ背面・非表示の棟や階にある間は吹き出しを隠し、戻ったら再表示する。
3. 「ここから出発」「ここへ行く」で端点を指定する。「地図で選ぶ」を有効にすると入力候補を閉じ、選択中の案内がある地図へスクロールする。地図での指定中は、場所を選んだ時点で指定を完了し、吹き出しを表示せず選択の強調だけを残す。
4. 平面図の選択・キーボードフォーカスの強調は実際の多角形に沿い、部屋・経路より前面の専用レイヤーで表示する。強調はクリック判定を遮らない。選択の強調は部屋だけに限定しない。立体図では部屋・WC・EV・階段・AEDを同じ仕組みで発光させ、別の場所を選ぶと前の強調を解除する。
5. 選択を解除したら、詳細とすべての強調を解除する。表示モードの切り替えでは、残っている選択を新しい表示へ反映する。

立体図キャンバスを使えない操作方法にも対応するため、検索と階内の場所一覧からも部屋・設備を選べるようにする。門の選択ではキャンパス図を表示する。

## 画面の操作領域・道順

- スマートフォンではボタンを44px以上の高さ・幅にそろえる。チェックボックスもラベルを含む44px以上の操作領域を確保する。
- 入力・道順の本文は16px、操作名や補足は原則14px以上とし、ブランドの補助表記は12pxとする。SVG内の文字は地図座標に合わせて描画する。
- 道順は選択中の区間と全区間に対する位置を表示し、「前へ」「次へ」と開閉式の「道順一覧」で選べるようにする。最初・最後の区間では対応する移動ボタンを無効にする。
- 「地図で確認」で選択中の区間を再表示し、地図へスクロールする。経路計算時に最初の区間へ自動移動しない。
- 道順を閉じても区間と経路を保持し、「道順を再表示」で同じ区間に戻る。経路の解除・検索失敗時は再表示できる古い道順を残さない。
- 参考ルートには現地未確認の接続が含まれることを、移動条件の近くに表示する。

## スマートフォンのルート編集

- 幅899px以下では地図の直上に出発地・目的地・移動条件の要約と編集ボタンを表示する。幅900px以上ではサイドバーで編集する。
- スマートフォンの編集欄は画面下から開くモーダルパネルに配置する。背景の操作・スクロールを止め、キーボードフォーカスをパネル内に保つ。端末の表示領域の変化に合わせて高さと下端を調整する。
- 開いたときはパネルの見出しへフォーカスし、入力欄への自動フォーカスでソフトウェアキーボードを開かない。入力欄を選んだときに入力を開始する。編集中の画面幅変更では入力欄を複製せず、同じ編集欄を移動する。
- 「地図を見る」・閉じるボタン・背景のタップ・Escapeでパネルを閉じ、編集ボタンへフォーカスを戻す。入力途中の文字、確定した端点、移動条件は保持する。要約では未確定の入力を区別する。
- 経路がある場合、パネルを閉じたときと「地図で確認」を押したときは、地図と道順の見出し・現在の案内の冒頭が画面内に入る位置へスクロールする。道順を閉じている場合は再表示ボタンを見せる。経路がない場合、パネルを閉じても要約欄を表示し、入力状態やエラーを確認できるようにする。
- 「地図で選ぶ」ではパネルを閉じてから選択中の案内へスクロールする。編集パネルを開き直すと地図での指定モードを解除する。
- 経路未登録などのエラーや階段回避の代替経路の説明は、パネルを閉じても要約欄に表示する。概要と編集欄の両方を同じ検索状態から更新する。

## 平面図の表示・入力

- ＋／−ボタンは同じ44px四方の操作領域を持ち、文字幅や端末幅で寸法を変えない。
- 1本指・マウスのドラッグで移動し、2本指のピンチで拡大縮小する。2本指の中央にある地図上の地点を保ち、中央の移動によるパンも反映する。
- 指が増減したときは現在の表示を新たな基準にし、片指を離して移動を続けても地図を跳ねさせない。
- ドラッグ・複数指の操作・キャンセル後に場所を誤選択しない。通常のタップとキーボードの選択は維持する。
- 棟・階・表示モードの切り替えや「全体を表示」の操作では進行中のジェスチャーを終了する。拡大率の上下限は＋／−ボタンと共通にする。

## 立体図の表示・入力

- 初期表示は選択中の建物の全階。全階表示を外すと、選択中の階だけを表示する。
- 展開スライダーを動かすと全階表示へ切り替える。展開率と表示状態を画面に表示し、操作できるのに見た目が変わらない状態を避ける。
- 展開位置は各階の基準高さと積層順から求める。B1→1Fのような階番号の欠番や0階を扱えるようにする。
- スライダーを戻したら元の高さへ戻す。展開中の経路も同じ変換を使う。
- 同じ棟・表示中の連絡棟群の部屋や設備を選択してもカメラ位置・方向・拡大率を変更しない。その範囲外の場所を検索・選択した場合は、新しい表示範囲を収める。全階表示・単一階表示と階の間隔は保持する。必要な場合は「全体を表示」を使う。
- 立体図の緑・赤のピンは経路全体の出発地・目的地だけに表示する。表示区間の途中の端は、別階・屋外への中継地点を紫のひし形で表示する。表示対象が1地点だけの場合も端点の種類に応じたマーカーを表示する。
- 非表示の棟・階は選択対象に含めない。複数階が重なる場合は、手前の可視メッシュを選択する。特定階を選びたい場合は単階表示または場所一覧を利用する。
- 回転・パンなどのドラッグ、右ボタン操作、ピンチ、キャンセルされたタッチは、場所のクリックとして扱わない。ポインターが元の位置へ戻っても、途中でドラッグしていれば選択しない。
- WebGLを開始できない場合は説明を表示し、平面図・検索・経路指定を引き続き利用可能にする。

## 経路案内

原則として通路に面する側へ代表点を置き、廊下から線を伸ばす。正確な扉位置は必須とせず、通路に面する側が一面ならその面を使用する。別の部屋や立入不可区画を横切る場合だけ個別の例外を登録する。

登録されたノードと接続だけを使い、標準・階段回避・屋内優先・階段優先を選べるようにする。道順は棟と階を保持し、明示的なカード操作でその場所を確認できるようにする。

模式図で同棟に両端がある場合は、連絡棟群の範囲からの出入り回数を先に抑え、次に既知の階移動数と昇降量未確認の階段・スロープ・EV接続数の合計、選択条件の参考評価値を比較する。準備済みの連絡棟群の別棟間では、既知の階移動の逆行・行き過ぎを抑え、選択条件の参考評価値で比較する。昇降量未確認の階段区間数や屋外への出入り回数だけで長い館内迂回を優先しない。棟間・屋外への移動は選択条件の参考評価値で直接比較し、昇降のある近道を一律に後回しにしない。階段回避で経路がない場合は同じ確認条件で階段区間が最少の代替経路を探索し、階段が必要な注意を表示し続ける。同数なら参考評価値で比較する。完全に未接続の場合も理由を結果欄に残す。評価値は描画座標から独立させ、図の縮尺・配置変更だけでは経路を変えない。同階の接続がない区画への必要な他階経由は許可する。同棟の館内移動を、屋外経由では階番号を比較できないことだけを理由に迂回しない。管理用の接続は構造として保持しても、公開案内・代替経路には使わない。門・棟間の移動では登録済みの館内通り抜けを許可する。屋内優先は屋内・屋根付き・屋外または未確認を区別する。屋外の階段・スロープも概要に表示し、昇降量が不明ならその旨を示す。校正済みの実寸地図では距離を基準にする。

模式座標のままでは実距離・所要時間を表示しない。多目的トイレの種別や階段回避フラグから、車椅子で通行できると判定しない。現地未確認の接続は除外可能にする。

## 屋外の階層と周辺道路

連絡橋は地上通路と別の層として扱い、平面上の交差や同一座標だけでは接続しない。6号館側は階段とスロープを別経路として登録し、12号館・17号館間は階段で23号館側の地上通路へ接続する。19号館の購買部側出入口付近の地上通路からも、階段で17・12号館間の連絡橋の曲がり角へ接続する。両階段を別の昇降地点として保持し、階段回避には使用しない。スロープも昇降のある接続として探索・概要・道順へ反映し、高低差が未確認なら架空の階数を補わない。12・17号館側のスロープは未登録で、階段回避では地上迂回路を使用する。東門から2号館東側を通り3号館側へ進む直通路も登録する。

周辺道路は空中写真から簡略化した薄い背景線として表示する。表示用の道路線と案内用の接続は別に保持し、道路線から歩行経路や交差点を自動生成しない。道路沿いの歩行区間も、通行情報に基づく明示的な屋外エッジとして登録できる。幅員・歩道・横断位置・通行条件は現地照合待ちとする。

画面の説明は入口の向き・案内先などに絞り、出典・仮定・確認待ちは[資料・調査記録](survey-notes.md)へ分ける。道順は通路の細かい分岐を一枚ずつ表示せず、出入口・階段・連絡通路・目的地を中心にまとめる。
