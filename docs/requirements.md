# Uniview 要件と操作仕様

## 目的

神奈川大学 横浜キャンパス内で、建物・部屋・トイレなどの設備・門を探し、登録された接続に沿った経路を確認できる非公式の案内サイトを提供する。

公開物はHTML・CSS・JavaScript・JSONからなる静的サイトとする。地図の表示、検索、場所の選択、経路計算はブラウザー内で完結し、専用サーバー・データベース・ログインを必須にしない。

## 場所とデータ

| 対象 | 選択・検索 | 現在の経路データ |
| --- | --- | --- |
| 建物 | キャンパス図・建物選択で表示対象を変更 | 屋外・棟間は未登録 |
| 部屋 | 平面図・3D・検索・階内の場所一覧で選択 | 3号館の34室、20号館の95室に通路側の案内地点あり。20号館の奥の13室は指定した手前の部屋まで案内 |
| WC・EV・階段・AED | 部屋と同じ選択・強調・経路指定の仕組み | 明示された入口・乗り場だけを使用。未確認の接続は参考扱い |
| 正門・東門・新東門・西門 | キャンパス図・門一覧・検索で選択 | 門と建物を結ぶ屋外経路は未登録 |

20号館1Fの建物出入口3か所は、平面図・3D・検索・場所一覧で選択でき、館内の参考経路に接続する。屋外経路との接続は別途登録する。

建物内の場所は棟ID・階を持ち、門はキャンパス上の場所として扱う。門に架空の棟ID・階番号を割り当てない。校舎配置図と室内図の模式座標を混同しない。

場所の選択と、経路の登録状態は別に扱う。入口・屋外経路が未登録でも場所は出発地・目的地として記憶できる。経路がない場合は対象と不足する接続を明示し、近隣の別地点へ自動で置き換えたり、直線で仮の経路を表示したりしない。奥の部屋に限り、同じ階の通路に面した部屋を `approachRoomId` で明示し、その部屋の通路側まで案内できる。指定された部屋の名前を保持し、案内終点の違いを詳細・概要・道順に表示する。

建物・階・設備・門はJSONで管理する。出典と確認状態を記録し、棟を増やすたびに画面の分岐を追加する設計にしない。

## 状態の分離

| 状態 | 役割 | 他の状態への影響 |
| --- | --- | --- |
| 表示モード | キャンパス・平面図・3D | 出発地・目的地を保持する |
| 表示する棟・階 | 図面と階内の場所一覧を指定 | 出発地・目的地を変更しない |
| 選択した場所 | 強調表示と共通の詳細・アクションを表示 | カメラを移動しない |
| 出発地・目的地 | 検索または選択した場所から明示的に指定 | 経路計算だけで表示階・選択・カメラを変更しない |
| 地図で指定中の対象 | 出発地または目的地の一方 | 設定完了・キャンセル・Escapeで解除する |
| 3Dの全階表示・展開率 | 可視階と階間隔を指定 | 部屋・設備の選択や経路計算で変更しない |
| カメラ | 位置・方向・拡大率 | ドラッグ等の手動操作、視点リセット、3Dへの切り替え、建物選択、明示的な道順カード操作で変更する |

## 共通の場所選択

1. 平面図・3D・検索・場所一覧・門一覧から同じ場所IDを選択する。
2. 選択した場所の名前と登録状態を、その場所を指す地図上の吹き出しに表示する。「ここから出発」「ここへ行く」を吹き出し内に配置する。
   - 吹き出しは地図に重ね、表示・非表示によってページのレイアウトやスクロール位置を変更しない。
   - 平面図・キャンパス図のパン／ズーム、3Dのカメラ操作・階の展開、画面サイズの変更に追従する。
   - 地図の端では吹き出しを表示範囲内に収める。選択位置が画面外・カメラ背面・非表示の棟や階にある間は吹き出しを隠し、戻ったら再表示する。
3. 「ここから出発」「ここへ行く」で端点を指定する。地図での指定中なら、場所を選んだ時点で指定を完了する。
4. 選択の強調は部屋だけに限定しない。3Dでは部屋・WC・EV・階段・AEDを同じ仕組みで発光させ、別の場所を選ぶと前の強調を解除する。
5. 選択を解除したら、詳細とすべての強調を解除する。表示モードの切り替えでは、残っている選択を新しい表示へ反映する。

3Dキャンバスを使えない操作方法にも対応するため、検索と階内の場所一覧からも部屋・設備を選べるようにする。門の選択ではキャンパス図を表示する。

## 3Dの表示・入力

- 初期表示は選択中の建物の全階。全階表示を外すと、選択中の階だけを表示する。
- 展開スライダーを動かすと全階表示へ切り替える。展開率と表示状態を画面に表示し、操作できるのに見た目が変わらない状態を避ける。
- 展開位置は各階の基準高さと積層順から求める。B1→1Fのような階番号の欠番や0階を扱えるようにする。
- スライダーを戻したら元の高さへ戻す。展開中の経路も同じ変換を使う。
- 部屋や設備を選択してもカメラ位置・方向・拡大率を変更しない。必要な場合は「視点リセット」を使う。
- 非表示の棟・階は選択対象に含めない。複数階が重なる場合は、手前の可視メッシュを選択する。特定階を選びたい場合は単階表示または場所一覧を利用する。
- 回転・パンなどのドラッグ、右ボタン操作、ピンチ、キャンセルされたタッチは、場所のクリックとして扱わない。ポインターが元の位置へ戻っても、途中でドラッグしていれば選択しない。
- WebGLを開始できない場合は説明を表示し、平面図・検索・経路指定を引き続き利用可能にする。

## 経路案内

原則として通路に面する側へ代表点を置き、廊下から線を伸ばす。正確な扉位置は必須とせず、通路に面する側が一面ならその面を使用する。別の部屋や立入不可区画を横切る場合だけ個別の例外を登録する。

登録されたノードと接続だけを使い、最短・階段回避・屋内優先・階段優先を選べるようにする。道順は棟と階を保持し、明示的なカード操作でその場所を確認できるようにする。

模式座標のままでは実距離・所要時間を表示しない。多目的トイレの種別や階段回避フラグから、車椅子で通行できると判定しない。現地未確認の接続は除外可能にする。

## 検証と段階的な拡張

現段階では、3号館の6フロアで室内閲覧・参考経路と共通操作を検証し、20号館の4フロアでは室内閲覧・設備選択・出入口からの参考経路・奥の部屋の案内範囲を検証する。次に他棟の図面を追加し、屋外通路と建物・門の実際の出入口を確認して接続する。現在地の自動測位、開放状況のリアルタイム更新、避難誘導は別途要件化する。

回帰確認では、機能ごとの単体確認に加え、3Dで部屋を選び出発地にする→WCを選び目的地にする→経路を表示する→展開率を変更する一連の操作を確認する。発光、端点、表示階、展開率、カメラへの影響を同時に検査する。実ブラウザー・WebGL・モバイルでの描画と操作の確認は、DOMやCPU上の3Dテストとは分けて記録する。
