# 経路の接続状況と点検方法

## 点検範囲

登録済み12棟・1,047区画について、異なる棟の全室ペアを往復別に点検する。対象は941,296組で、標準・階段回避・屋内優先・階段優先の4条件を使う。階段回避以外の3条件は、経路の選び方が異なるが、通行可能な接続の集合は同じである。参考ルートを含む状態の点検であり、現地確認済みの経路を意味しない。未登録の建物や門は、この部屋間集計には含まれない。

`npm run audit:data -- --json audit-report.json` の `campusCoverage` に、全体と棟の方向別の件数・代表例を保存する。`--mode accessible`・`indoor`・`stairs` で条件を指定できる。

| 分類 | 標準 | 階段回避 | 意味 |
| --- | ---: | ---: | --- |
| 接続あり | 339,268 | 237,944 | 指定条件で登録済みの経路がある |
| 案内地点なし | 2,024 | 2,024 | 片方以上の部屋の案内地点が未登録 |
| 接続なし | 600,004 | 600,004 | 標準でも接続がなく、接続情報の追加が必要 |
| 条件による除外 | 0 | 101,324 | 標準では接続するが、階段回避では接続しない |

集計は距離評価と独立したグラフ到達性で行う。片道・通行止めを反映し、手前の部屋を共有する奥の部屋も元の部屋番号で数える。監査は経路を自動追加せず、確認候補として報告する。登録内容を変更した場合は件数も変わる。

| 対象 | 現在の状態 | 次に確認する情報 |

| 7〜10号館 | 棟群内は1〜6Fの対応階を参考接続するが、屋外経路へ未接続。2Fは旧資料による仮登録 | 日常利用する出入口と屋外通路、2Fの現況と階段・EVの対応 |

標準モードで到達できない部屋間の組み合わせは上記のいずれかに該当する。回帰テストでは、それ以外の未接続が増えた場合に検出する。

正門の屋外経路、6号館1Fの実験室内階段、23号館B2の階段3も接続未登録であり、表示だけを保持する。20号館の残り2出入口と17号館3F出入口には屋外接続がないが、別の登録済み出入口から届く区画は上記の部屋間集計では接続ありになる。

階段回避では、5号館の唯一の屋外接続が外階段のため、他棟と接続しない。19号館では1FのEV乗降を登録していないため、屋外からの階段回避は購買部側の区画に限られる。これは接続漏れの判定と分ける。未確認の通路やEV乗降を補完しない。

## 経路選択と表示

同じ棟・準備済みの連絡棟群では、昇降の少なさと不要な出入りの少なさを優先する。棟間・屋外への移動は選択条件の参考評価値で比較し、階段のある近道も候補にする。階段回避の通行制約は維持する。

- 23-101と19-101の標準経路は、17・12号館間の連絡橋と19号館側の階段を通る。階段回避では17号館を迂回する地上経路を使う。
- 5-201と23-101は、外階段を含む標準経路がある。階段回避では経路がなく、その理由と標準モードの代替を表示する。
- 参考評価値は実測距離や歩行時間ではない。現地調査後に距離・高低差・階段の負担を反映して調整する。

全組み合わせの接続点検に加え、回帰テストで両方向の実際の探索結果、階段回避、確認済み接続のみの制約、画面での条件切り替えを確認する。同棟内の全室ペア点検は引き続き不要な階移動を検出する。
